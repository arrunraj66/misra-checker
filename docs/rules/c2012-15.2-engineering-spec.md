# MISRA C:2012 Rule 15.2 engineering specification

Status: Implemented; independent validation pending

This document is an original engineering specification. It intentionally does
not reproduce licensed normative wording, amplification, rationale, or example
text. The controlled licensed MISRA source remains authoritative.

## Checker objective

Identify a resolved `goto` whose target label appears earlier than, or at the
same source-order position as, the jump. A forward jump to a subsequently
declared label produces no Rule 15.2 finding.

## Applicability and classification

- C language profiles: C90 and C99.
- Category: Required.
- Analysis class: Decidable.
- Scope: Single translation unit.
- Primary diagnostic location: the `goto` keyword expansion location.
- Certainty for a successfully parsed and resolved jump: Definite.

## Required analysis facts

For every `GotoStmt` written in the primary translation unit, the Clang adapter
records:

- jump source location;
- target-label source location;
- source-order relationship between jump and target;
- whether the jump originated in a macro expansion;
- whether the target label originated in a macro expansion.

Clang resolves labels within the containing function before the rule evaluator
runs. A translation unit that cannot be parsed successfully is treated as an
analysis failure rather than as compliant.

## Detection algorithm

1. Visit each resolved Clang `GotoStmt`.
2. Obtain the jump and target-label source locations.
3. Preserve expansion locations for diagnostics and macro-origin flags for
   evidence.
4. Ask Clang's source manager for their translation-unit ordering using the
   original locations, including macro locations.
5. Emit `misra-c2012-15.2-backward-goto` when the target is not later than the
   jump.
6. Emit no Rule 15.2 finding for a forward jump.

## Verification cases

| Test class | Fixture or test | Expected result |
|---|---|---|
| Unit, forward | `rule_15_2_test` | No finding |
| Unit, backward | `rule_15_2_test` | One definite finding |
| Direct forward jump | `rule_15_2/forward.c` | No Rule 15.2 finding |
| Direct backward jump | `rule_15_2/backward.c` | One Rule 15.2 finding |
| Macro forward jump | `rule_15_2/macro_forward.c` | No Rule 15.2 finding |
| Macro backward jump and label | `rule_15_2/macro_backward.c` | One Rule 15.2 finding |
| CLI integration | `cli_analyze_rule_15_2_violation` | Required diagnostic and exit code 1 |
| Registry accounting | `rule_registry` | 2 implemented and 141 scaffold rules |

## Known limitations and validation work

- Independent oracle review has not been completed.
- Supported behavior is currently pinned to Clang/LLVM 14 and must be
  regression-tested before a frontend upgrade.
- Compiler-extension behavior is accepted only when Clang successfully parses
  the configured translation unit.
- Complete nested macro expansion stacks are not yet included in diagnostics.
- Diagnostic output currently exposes the primary jump location; the retained
  target location will be added as a related location in the evidence schema.
- Qualification coverage, mutation testing, multi-platform testing, and an
  external conformity assessment remain outstanding.
